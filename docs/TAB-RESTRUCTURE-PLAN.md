# Tab 重组方案 - 配置作用域清晰化

本文档详细描述了重新设计的 6 Tab 配置体系，解决"牵一发而动全身"的配置混乱问题。

## 核心设计目标

1. **消除配置作用域混乱**：明确每个配置项的影响范围，避免修改一个配置影响多个功能
2. **去除隐式依赖**：AI 判定不再依赖传统规则，两者完全独立
3. **明确硬性约束边界**：硬性约束始终执行，不受 AI/传统模式影响
4. **分离共享配置**：明确标注哪些配置被多个功能共享
5. **优化 Tab 分类逻辑**：按功能场景而非技术分类组织配置

## 方案概述

将现有 7 个 Tab 重组为 6 个，消除配置依赖混乱：

| 原 Tab | 新 Tab | 变更说明 |
|--------|--------|---------|
| 工作台 | 工作台 | 保持不变 |
| AI 配置 | AI 能力 | 重命名，明确标注为"共享配置" |
| 投递判定 | ~~删除~~ | 合并到"投递过滤" Tab |
| 传统投递 | ~~删除~~ | 合并到"投递过滤" Tab |
| 对话通知 | 消息管理 | 重命名，分离消息回复延迟配置 |
| 运行记录 | 运行日志 | 重命名，保持功能 |
| 账户 | 账户数据 | 重命名，保持功能 |

## 配置作用域清晰化表格

| 配置项 | 所属 Tab | 作用范围 | 被哪些功能使用 | 依赖其他配置 |
|--------|---------|----------|----------------|--------------|
| AI 模型配置 | AI 能力 | 全局共享 | AI 代聊 + AI 投递判定 | 无 |
| 提示词预设 | AI 能力 | 全局共享 | AI 代聊 + AI 投递判定 | 无 |
| 硬性约束（8个） | 投递过滤 | 投递流程 | AI 模式 + 传统模式 | 无 |
| AI 智能过滤（7个） | 投递过滤 | 投递流程 | 仅 AI 模式 | 无（已删除 includeTraditionalSnapshot） |
| 传统软过滤（5个） | 投递过滤 | 投递流程 | 仅传统模式 | 无 |
| 投递间隔 | 投递过滤 | 投递流程 | AI 模式 + 传统模式 | 无 |
| 消息回复延迟 | 消息管理 | 消息回复 | AI 代聊 | 无 |
| 记忆策略 | 消息管理 | AI 代聊 | AI 代聊 | 无 |

## 1. 工作台

**定位**：投递操作的核心控制中心，提供一键启动、实时监控和快速配置。

**配置作用域**：仅影响当前投递任务的执行参数，不影响其他功能。

### 1.1 投递统计面板
展示今日投递成效，一目了然。

- **今日投递成功** - 绿色数字，显示成功投递数量
- **今日投递失败** - 红色数字，显示失败投递数量
- **清理投递记录** - 按钮，重置统计数据

### 1.2 投递参数配置
快速调整投递行为，无需切换页面。

- **单次处理限制** - 数字输入，-1 表示不限制，建议 20-50
- **按条件收藏** - 开关，开启后改为收藏模式而非投递
- **推荐页无限循环** - 开关，自动刷新推荐页持续投递

### 1.3 投递控制
一键启动/停止，简单直接。

- **开始投递 / 停止投递** - 主按钮，根据状态切换文字
- **浮动停止按钮** - 投递中时显示在右下角，方便随时停止

### 1.4 实时状态监控
查看最近操作，掌握投递进度。

- **实时操作记录** - 标题栏，带状态指示灯（投递中为绿色）
- **日志列表** - 显示最近 10 条操作记录，自动滚动到最新
- **清空记录** - 按钮，清空当前显示的日志

### 核心价值
- **快速启动**：一键开始投递，无需复杂配置
- **实时反馈**：投递进度和结果即时可见
- **灵活控制**：随时调整参数或停止投递

## 2. AI 能力

**定位**：AI 基础服务的统一配置中心，包含模型配置和提示词管理。

**重要说明**：此 Tab 中的配置被 **AI 代聊** 和 **AI 投递判定** 两个功能共享。修改此处配置会同时影响这两个功能。

**配置作用域**：全局共享，影响所有使用 AI 的功能。

### 2.1 AI 模型配置
选择 AI 供应商和模型，配置 API 连接。

- **供应商选择** - 下拉框：自定义 / Deepseek / 火山引擎 / 硅基流动 / 月之暗面 / Open Router
- **模型名称** - 下拉框，根据供应商动态显示可用模型
- **API Key** - 密码输入框，保护敏感信息
- **Base URL** - 文本输入框，自定义 API 端点
- **超时设置** - 数字输入框，单位秒，建议 30-60
- **测试连接** - 按钮，验证 API 配置是否正确

### 2.2 提示词预设管理
管理 AI 对话的提示词模板，提升回复质量。

- **全局预设列表** - 下拉选择，所有模型共用的预设
- **模型专属预设** - 列表，为当前模型定制的预设
- **添加预设** - 按钮，创建新的提示词预设
- **编辑预设** - 表单：预设名称 + 提示词内容
- **删除预设** - 按钮，移除不需要的预设

### 2.3 保存配置
- **保存 AI 配置** - 主按钮，保存所有 AI 相关配置

### 核心价值
- **统一管理**：所有 AI 基础配置集中在一处，避免分散
- **灵活配置**：支持多供应商、多模型切换
- **共享透明**：明确标注配置被哪些功能共享，避免意外影响

## 3. 投递过滤

**定位**：职位筛选规则的统一配置中心，包含硬性约束、AI 智能过滤和传统软过滤三个独立区域。

**配置作用域**：仅影响投递流程中的职位筛选，不影响 AI 代聊等其他功能。

### 3.1 硬性约束区域

**说明**：硬性约束始终执行，不受 AI/传统模式影响。这些规则是投递的底线，无论选择哪种模式都会先执行。

**配置项**：
- **自动过滤猎头岗位** - 复选框，排除猎头发布的职位
- **仅投递 BOSS 刚刚活跃/在线** - 复选框，提升回复率
- **公司名黑名单** - 复选框 + 多选输入框，例如：某某外包公司
- **岗位名黑名单** - 复选框 + 多选输入框，例如：销售、客服、运营
- **薪资范围** - 复选框 + 文本输入，格式：15-30（月薪 k）
- **公司规模范围** - 复选框 + 文本输入，格式：100-9999（人数）

**作用范围**：AI 模式 + 传统模式都会执行

### 3.2 AI 智能过滤区域

**说明**：开启 AI 智能过滤后，AI 将分析岗位 JD 和您的简历进行精准匹配。AI 判定完全独立，不读取传统软过滤规则。

**互斥逻辑**：开启 AI 智能过滤后，传统软过滤区域自动禁用（灰色不可编辑）。

**配置项**：

#### 3.2.1 智能过滤开关
- **启用 AI 智能过滤** - 主开关，关闭后使用传统软过滤规则

#### 3.2.2 判定上下文
- **包含求职者个人信息** - 开关，将学历、经验等加入判断
- **~~包含传统规则摘要~~** - **已删除**，AI 判定不再依赖传统规则

#### 3.2.3 重点过滤规则
- **核心技能要求** - 多选输入框，例如：Vue3、TypeScript、Node.js
  - 提示：AI 将重点匹配这些技能，JD 中不包含则降低评分
- **绝对排除关键词** - 多选输入框，例如：外包、驻场、出差
  - 提示：AI 识别到这些词将直接拒绝该岗位

#### 3.2.4 异常处理策略
- **AI 请求失败策略** - 下拉选择
  - 拒绝投递（默认，更保守）
  - 回退到传统投递规则
- **AI 结果无法解析策略** - 下拉选择
  - 拒绝投递（默认，更保守）
  - 回退到传统投递规则

#### 3.2.5 测试与保存
- **恢复默认配置** - 文本按钮，重置为推荐配置
- **测试重点分析** - 警告按钮，预览 AI 输入数据（JSON 格式）
- **保存判定规则** - 主按钮，保存所有 AI 判定配置

**作用范围**：仅 AI 模式执行

### 3.3 传统软过滤区域

**说明**：通过明确的条件筛选职位，适合有明确要求的用户。传统软过滤与 AI 智能过滤互斥，只能选其一。

**互斥逻辑**：开启传统软过滤后，AI 智能过滤区域自动禁用（灰色不可编辑）。

**配置项**：

#### 3.3.1 传统规则总开关
- **启用传统软过滤规则** - 主开关
- **说明提示** - "关闭后将跳过传统软过滤，仅保留硬性约束"

#### 3.3.2 活跃度过滤
- **启用活跃度过滤** - 复选框
- **活跃度选择** - 多选：刚刚活跃 / 本周活跃 / 本月活跃

#### 3.3.3 融资阶段过滤
- **启用融资阶段过滤** - 复选框
- **融资阶段选择** - 多选：未融资 / 天使轮 / A轮 / B轮 / C轮 / D轮及以上 / 已上市 / 不需要融资

#### 3.3.4 JD 关键词过滤
- **启用 JD 关键词过滤** - 复选框
- **排除关键词列表** - 多选输入框，例如：驻场、出差、加班

#### 3.3.5 招呼语设置
- **自定义招呼语** - 文本域，支持多行输入

**作用范围**：仅传统模式执行

### 3.4 投递频率控制

**说明**：避免频繁投递被限制，此配置对 AI 模式和传统模式都生效。

**配置项**：
- **启用投递间隔** - 复选框
- **间隔时间** - 数字输入框，单位秒，建议 3-5

**作用范围**：AI 模式 + 传统模式都会执行

### 3.5 保存配置
- **保存投递过滤设置** - 主按钮，保存所有投递过滤配置

### 核心价值
- **配置隔离**：硬性约束、AI 智能过滤、传统软过滤三者边界清晰
- **互斥逻辑**：AI 和传统软过滤互斥，避免配置冲突
- **独立判定**：AI 判定不再依赖传统规则，完全独立
- **灵活组合**：硬性约束 + AI 智能过滤，或硬性约束 + 传统软过滤

## 4. 消息管理

**定位**：AI 自动回复和对话管理中心，解放双手，智能沟通。

**配置作用域**：仅影响 AI 代聊功能，不影响投递流程。

### 4.1 AI 代聊总开关
控制是否启用 AI 自动回复。

- **启用 AI 代聊服务** - 主开关
- **说明提示** - "开启后系统将自动接管 BOSS 上的新消息并进行回复"

### 4.2 消息回复延迟设置

**说明**：此配置仅影响 AI 代聊的消息回复延迟，不影响投递间隔。投递间隔配置在"投递过滤" Tab 中。

**配置项**：
- **启用延迟回复** - 复选框
- **延迟时间** - 数字输入框，单位秒，建议 5-15
- **说明提示** - "收到消息后延迟 X 秒进行回复，更自然"

**作用范围**：仅影响 AI 代聊的消息回复，不影响投递流程

### 4.3 快捷交互处理
预设常用回复，提升沟通效率。

- **预设提问（主动发起）** - 复选框 + 文本域
  - 示例：您好，请问该岗位是否双休？是否有加班补贴？
  - 用途：投递成功后主动发起提问
- **婉拒回复术语（手动拒绝时）** - 复选框 + 文本域
  - 示例：非常感谢您的认可，但经过考虑我觉得该岗位与我目前的发展方向不太契合...
  - 用途：手动拒绝时使用的礼貌回复

### 4.4 高意向转换策略
识别高意向对话，自动转人工接管。

- **触发高意向后，自动暂停 AI 代聊交由人工接管** - 复选框
- **触发条件**（满足其一即可）：
  - **双方对话轮数 ≥** - 数字输入框，建议 5 轮
  - **HR 消息包含** - 多选输入框，例如：面试、微信、电话、简历

### 4.5 邮件通知设置
及时获知对话进展。

- **每轮对话均发送邮件通知** - 复选框
- **仅在触发高意向时通知（推荐）** - 复选框，减少邮件干扰

### 4.6 AI 上下文记忆策略
控制 AI 如何记忆和总结对话历史。

- **启用上下文抽象总结** - 复选框
- **作用域** - 下拉选择
  - 会话级（当前 HR）：每个 HR 独立记忆
  - 岗位级（同种岗位）：同类岗位共享记忆
  - 全局级（所有沟通）：所有对话共享记忆
- **触发摘要阈值** - 数字输入框，建议 12 条消息
- **最大追溯轮数** - 数字输入框，建议 20 轮
- **保存记忆策略** - 按钮，保存记忆配置

### 4.7 无效会话清理
**（ConversationCleaner 组件嵌入）**

清理无效对话，保持列表整洁。

- **扫描待清理会话** - 按钮，自动识别无效对话
- **清理条件** - 多选：无回复 / 已拒绝 / 已过期
- **批量选择** - 复选框，全选或部分选择
- **批量删除** - 按钮，删除选中的会话
- **删除进度** - 进度条，显示删除进度和结果

### 4.8 保存配置
- **保存全盘对话设置** - 主按钮，保存所有 AI 代聊配置

### 核心价值
- **解放双手**：AI 自动回复，无需时刻盯着消息
- **智能转换**：识别高意向对话，及时人工介入
- **记忆管理**：AI 记住对话历史，回复更连贯
- **会话清理**：保持对话列表整洁，减少干扰

## 5. 运行日志

**定位**：完整的日志查看和分析中心，追踪所有操作记录。

**配置作用域**：只读，不影响其他功能。

### 5.1 日志过滤工具栏
快速定位需要的日志。

- **时间范围选择器** - 范围选择，格式：HH:mm - HH:mm
- **日志级别下拉框** - 单选：全部级别 / Error / Warn / Info / Debug
- **关键词搜索框** - 文本输入，支持模糊搜索
- **清空日志按钮** - 危险按钮，清空所有日志记录

### 5.2 日志表格
以表格形式展示日志，信息清晰。

- **记录时间** - 列宽 160px，格式：HH:mm:ss.SSS
- **级别** - 列宽 100px，带颜色标签
  - Error：红色
  - Warn：橙色
  - Info：蓝色
  - Debug：灰色
- **AI 判定** - 列宽 120px，显示 AI 判断结果
  - 通过：绿色
  - 不通过：红色
  - 失败：橙色
  - 不可解析：灰色
- **判定理由 / 提示** - 列宽 240px，显示 AI 判断原因或提示信息
- **详细内容** - 最小宽度 300px，显示完整的日志消息

### 5.3 分页控制
处理大量日志，性能优化。

- **总数显示** - 显示日志总条数
- **每页条数选择** - 下拉选择：10 / 20 / 50 / 100
- **上一页 / 下一页** - 按钮，翻页导航
- **页码跳转** - 输入框，快速跳转到指定页

### 核心价值
- **完整记录**：保留所有操作日志，便于追溯
- **灵活过滤**：支持时间、级别、关键词多维度过滤
- **AI 分析**：自动解析 AI 判定结果，一目了然
- **性能优化**：分页显示，处理大量日志不卡顿

## 6. 账户数据

**定位**：个人信息和数据管理中心，管理简历和配置。

**配置作用域**：仅影响个人信息和简历数据，不影响其他功能。

### 6.1 基本信息编辑
维护个人联系方式。

- **手机号** - 文本输入框，用于接收通知
- **邮箱** - 文本输入框，用于接收邮件通知
- **保存基本信息** - 按钮，保存联系方式

### 6.2 在线简历导入
从 BOSS 直聘导入在线简历。

- **导入在线简历** - 按钮，一键导入
- **简历预览** - 文本域，只读，显示导入的简历内容
- **简历长度显示** - 文本，显示字符数，建议 ≥ 80 字符

### 6.3 附件简历上传
上传本地简历文件，AI 自动解析。

- **上传附件简历** - 文件选择按钮
- **支持格式** - 提示：PDF / DOC / DOCX
- **简历解析状态** - 提示：成功 / 失败 / 解析中
- **解析结果预览** - 文本域，显示解析后的简历内容

### 6.4 图片简历上传
上传简历截图，适用于特殊格式简历。

- **上传图片简历** - 图片选择按钮
- **支持格式** - 提示：JPG / PNG
- **图片预览** - 缩略图，显示上传的图片
- **删除图片** - 按钮，移除已上传的图片

### 6.5 配置备份与恢复
导出/导入配置，方便迁移或备份。

- **导出配置** - 按钮，导出为 JSON 文件
  - 包含：投递偏好、AI 配置、代聊设置等
- **导入配置** - 按钮，从 JSON 文件导入
  - 自动覆盖当前配置

### 6.6 敏感数据清除
清空所有本地数据，保护隐私。

- **清除所有本地数据** - 危险按钮，红色警告样式
- **确认对话框** - 二次确认，防止误操作
  - 提示：此操作不可恢复，将清除所有配置和简历数据

### 核心价值
- **简历管理**：支持多种简历导入方式，灵活便捷
- **配置备份**：导出/导入配置，方便迁移或恢复
- **隐私保护**：一键清除所有本地数据，保护个人隐私

## 重组优势

### 1. 消除配置作用域混乱

**问题**：原有配置体系中，修改一个配置会影响多个功能，用户不知道影响范围。

**解决方案**：
- **明确标注作用范围**：每个 Tab 顶部标注配置作用域
- **删除隐式依赖**：AI 判定不再依赖传统规则（删除 `includeTraditionalSnapshot`）
- **分离共享配置**："AI 能力" Tab 明确标注为"全局共享"
- **分离延迟配置**：投递间隔（3-5秒）vs 消息回复延迟（5-15秒）

### 2. 明确硬性约束边界

**问题**：原有代码中，硬性约束只在传统模式下执行，AI 模式下不执行，导致用户困惑。

**解决方案**：
- **硬性约束始终执行**：无论 AI 模式还是传统模式，硬性约束都会先执行
- **单独区域展示**："投递过滤" Tab 中单独展示硬性约束区域
- **明确标注**："始终执行，不受 AI/传统模式影响"

### 3. 实现 AI 和传统软过滤互斥

**问题**：原有设计中，AI 判定和传统软过滤可以同时开启，导致配置冲突。

**解决方案**：
- **互斥逻辑**：开启 AI 智能过滤后，传统软过滤区域自动禁用（灰色不可编辑）
- **清晰边界**：AI 智能过滤和传统软过滤在 UI 上分为两个独立区域
- **独立判定**：AI 判定不再读取传统规则，完全独立

### 4. 优化功能分类

**问题**：原有 Tab 分类混乱，"AI 配置"和"投递判定"分离，"传统投递"和"对话通知"命名不准确。

**解决方案**：
- **按功能场景分类**：投递相关配置集中在"投递过滤" Tab
- **重命名 Tab**：
  - "AI 配置" → "AI 能力"（强调基础服务）
  - "对话通知" → "消息管理"（更准确）
  - "运行记录" → "运行日志"（更准确）
  - "账户" → "账户数据"（更准确）

### 5. 减少导航混乱

**问题**：原有 7 个 Tab，职责不清晰，用户难以找到需要的功能。

**解决方案**：
- **Tab 数量**：从 7 个减少到 6 个，降低认知负担
- **职责清晰**：每个 Tab 职责明确，配置作用域清晰
- **保持功能完整**：所有原有功能都保留，只是重新组织
