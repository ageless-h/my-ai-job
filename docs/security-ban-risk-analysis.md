# 封号风险根因分级（2026-02-28）

## Critical
- 高频自动化投递与连续失败重试叠加：`src/core/engine/push-engine.ts` 与 `src/core/platform/boss-platform.ts` 直接调用 `friend/add.json`，在异常情况下可持续重试，容易形成平台可识别的异常节奏。
- 自动代聊链路可触发自动发简历：`src/core/platform/boss-option.ts` 中 AI 回复后可直接调用 `sendResumeFile`，若无独立频控会持续触发高风险操作。

## High
- 推荐页无限循环会延长连续自动化时长：`src/features/job-assistant/components/AiJob.vue` 在开启 `imE` 时会刷新并自动恢复运行，若没有安全冷却会放大风险。
- 会话清理全量扫描+批量删除：`src/features/conversation-cleaner/services/conversation-cleaner.ts` 默认全量分析会话并支持批删，虽然有队列节流但行为集中度高。

## Medium
- 频控配置存在“有值但未统一门控”的风险：历史上 `pi`/`npi` 与 `PUSH_LIMIT` 只覆盖部分链路，投递成功后附加行为（消息/图片简历）缺少独立会话阈值。
- 自动化行为时序较固定：多处固定等待时间（如 800ms、1200ms）在长会话中可能形成可识别模式。

## 第一批治理原则
1. 单轮上限 + 每分钟上限 + 每日上限并行生效。
2. 连续失败熔断并进入冷却期，阻断异常风暴。
3. 投递后自动消息/图片简历与 AI 对话分别加会话级阈值与最小间隔。
4. 保持随机抖动与人工可暂停能力，避免持续刚性节奏。

## 第二批治理原则（本次）
1. 安全时段治理：默认仅在 08:00-22:00 执行自动投递/收藏，夜间自动暂停。
2. 推荐页无限循环闸门：按天限制自动刷新恢复次数，超过上限自动停止。
3. 会话清理限额：单轮扫描与单轮删除均设置上限，防止批量行为过于集中。
4. 行为节奏进一步随机化：删除流程增加随机间隔，降低固定频率特征。

## 第三批治理原则（本次）
1. 域名白名单治理：核心自动化链路仅允许在 `zhipin.com` 官方域名执行，异常域名直接阻断。
2. AI 对话安全时段同步：自动回复与自动发简历复用安全时段闸门，夜间自动停用。
3. 批量删除人工闸门：高风险批量删除（默认 20 条及以上）要求二次输入确认词。
4. 通知渲染防注入：AI 聊天气泡内容进行 HTML 转义，降低富文本通知注入风险。
5. 动态脚本注入硬化：socket 动态注入前增加来源域名、结构完整性与体积校验，异常即失败关闭。

## 第三批补强（Oracle复核后）
1. 安全时段门控从“仅启动时校验”升级为“循环内持续校验 + 翻页前复验”，防止跨时段继续自动执行。
2. AI 自动回复限流改为“执行前校验并预占位”，消除异步调用阶段的阈值穿透窗口。
3. 会话删除二次确认下沉到服务层，避免仅靠 UI 逻辑被绕过。
4. 人工确认阈值增加区间约束（5-100），防止异常配置导致闸门失效。
5. 静态脚本来源校验引入 `static.zhipin.com` 可信域，保持 fail-close 同时避免误拦截。

## 第四批补强（人工验证稳定暂停）
1. 在主循环、翻页前与重试前增加人工验证探测，命中后立即切换 `PAUSE` 并停止自动化动作。
2. 新增 BOSS 验证弹窗/验证 iframe 检测，识别滑块、人机验证、验证码等高风险信号。
3. 在投递接口响应中识别人工验证提示文案，命中后直接触发暂停，避免继续重试与连发。

## 第五批补强（全面修复）
1. 移除 `eval` 动态脚本执行，消息通道改为运行时能力探测与安全降级，避免代码注入面。
2. 收紧 userscript `connect` 白名单，并在 `GM_xmlhttpRequest` 与 AI 直连层增加 URL allowlist 校验。
3. 认证令牌从 `localStorage` 迁移为 session + TTL + 内存缓存，401 时自动清理。
4. 用户偏好存储迁移到 GM 存储并清理 localStorage 遗留，降低页面脚本可见面。
5. AI 配置主对象不再持久化明文 API key，改为独立密钥槽位存储。
6. 会话清理与 AI 对话接入“人工验证前置阻断”，确保检测到验证时不继续高风险动作。
7. 平台层投递重试内循环移除，统一由引擎层退避重试控制，避免重试风暴。
8. 修复投递上限文案分支 `include` 调用错误为 `includes`，防止上限路径误判。
