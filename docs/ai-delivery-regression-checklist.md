# AI投递/传统投递 回归清单

> 目标：验证“AI投递 + 传统投递”双入口、双总开关与回退策略在真实页面中的行为符合预期。

## 0. 准备

- 进入 BOSS 岗位列表页（建议使用测试账号）。
- 打开面板，确认存在两个页签：`AI投递` 与 `传统投递`。
- 为避免风控，控制操作节奏，不要连续高频触发投递。

## 1. 入口与开关可见性

1. 在 `AI投递` 页面确认可见：
   - `AI投递总开关`
   - `判断提示词`
   - `附加指令`
   - `包含求职者个人信息`、`包含传统规则摘要`
   - `AI请求失败策略`、`AI结果异常策略`
2. 在 `传统投递` 页面确认可见：
   - `传统投递总开关`
   - 传统过滤项（公司名、岗位名、薪资、活跃度等）

期望：UI字段完整，保存后刷新页面仍保留。

## 2. 互斥路径验证（核心）

### Case A: AI开 + 传统开

- 设置：
  - `AI投递总开关 = 开`
  - `传统投递总开关 = 开`
  - AI策略保持默认（`reject`）
- 触发一次匹配流程。

期望：仅走 AI 判定；传统规则不作为主判定链路执行。

### Case B: AI关 + 传统开

- 设置：
  - `AI投递总开关 = 关`
  - `传统投递总开关 = 开`
- 使用一条会被传统规则拦截的岗位数据触发匹配。

期望：传统规则生效，命中时出现相应不匹配原因。

### Case C: AI关 + 传统关

- 设置：
  - `AI投递总开关 = 关`
  - `传统投递总开关 = 关`
- 触发匹配。

期望：跳过传统过滤项（公司名/岗位名/薪资/活跃度等），仅保留基础状态检查（如已沟通检查）。

## 3. 回退策略验证

### Case D: AI请求失败 -> 回退传统

- 设置：
  - `AI投递总开关 = 开`
  - `传统投递总开关 = 开`
  - `AI请求失败策略 = fallback-traditional`
- 人为制造 AI 请求失败（如临时无效配置）。

期望：系统回退传统规则并继续判定；日志包含“已回退到传统投递规则”字样。

### Case E: AI结果不可解析 -> 回退传统

- 设置：
  - `AI结果异常策略 = fallback-traditional`
- 构造无法解析的 AI 返回内容。

期望：系统回退传统规则并继续判定；日志包含“已回退到传统投递规则”字样。

### Case F: 回退不可用保护

- 设置：
  - `AI投递总开关 = 开`
  - `传统投递总开关 = 关`
  - 任一回退策略设置为 `fallback-traditional`
- 触发 AI 失败或 AI 结果异常。

期望：不会回退，直接拒绝并给出“传统投递总开关已关闭，无法回退”相关原因。

## 4. 配置读写与迁移

1. 修改 AI 配置扩展项并保存，刷新后检查仍保留。
2. 恢复默认配置后手动保存，再刷新检查默认值是否生效。

期望：
- AI配置字段持久化正常。
- 旧配置用户首次进入时能正确补齐默认字段。

## 5. 验收结论模板

- 入口与字段：通过/不通过
- 互斥行为：通过/不通过
- 回退策略：通过/不通过
- 配置持久化：通过/不通过
- 风险备注：
  - 如存在偶发网络错误，需区分“真实功能问题”与“外部服务抖动”。
