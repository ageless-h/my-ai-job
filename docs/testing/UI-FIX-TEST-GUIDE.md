# UI修复测试指南

## 测试环境
- 浏览器：Chrome/Edge（推荐）
- 测试页面：https://www.zhipin.com/
- 用户脚本：安装最新构建的 `dist/ai-job-hunting.user.js`

## 测试清单

### 1. Z-index层级测试
**目标**：验证FAB按钮与侧边栏的层级关系正确

**步骤**：
1. 打开BOSS招聘页面
2. 点击FAB按钮展开侧边栏
3. 观察侧边栏是否完全覆盖FAB按钮（预期：是）
4. 点击侧边栏内的任何元素，确认可以正常交互（预期：可以）
5. 点击收起按钮，观察FAB按钮是否出现在最上层（预期：是）

**预期结果**：
- ✅ 展开时：侧边栏 z-index=99999，FAB z-index=99998
- ✅ 收起时：FAB z-index=100000，侧边栏 z-index=99997

---

### 2. 点击事件测试
**目标**：验证所有按钮点击事件正常工作

**步骤**：
1. 点击FAB按钮（展开/收起）- 应该立即响应
2. 点击侧边栏顶部的收起按钮 - 应该立即响应
3. 点击导航标签（工作台、AI配置等）- 应该立即切换
4. 在工作台中点击"清理投递记录"按钮 - 应该立即响应

**预期结果**：
- ✅ 所有按钮点击都能正常触发
- ✅ 没有点击穿透或点击无响应的情况

---

### 3. 动画同步测试
**目标**：验证动画与状态同步，无"幽灵"可点击区域

**步骤**：
1. 展开侧边栏，在动画进行中尝试点击侧边栏内容（预期：无响应）
2. 等待动画完成（0.4秒），再次点击侧边栏内容（预期：正常响应）
3. 收起侧边栏，在动画进行中尝试点击原侧边栏位置（预期：无响应）
4. 等待动画完成，点击FAB按钮（预期：正常响应）

**预期结果**：
- ✅ 动画期间侧边栏不可交互（pointer-events: none）
- ✅ 动画完成后立即恢复交互
- ✅ 没有"幽灵"可点击区域

---

### 4. Resize拖拽测试
**目标**：验证侧边栏宽度调整功能和内存泄漏修复

**步骤**：
1. 展开侧边栏
2. 将鼠标悬停在侧边栏左边缘（应该显示拖拽光标）
3. 按住鼠标左键拖拽调整宽度
4. 在拖拽过程中切换浏览器标签页
5. 切换回来，松开鼠标
6. 再次尝试拖拽（预期：正常工作）

**预期结果**：
- ✅ 拖拽调整宽度流畅
- ✅ 切换标签页时自动停止拖拽
- ✅ 没有内存泄漏（事件监听器正确清理）

---

### 5. 响应式布局测试
**目标**：验证移动端和不同屏幕尺寸下的显示

**步骤**：
1. 打开Chrome DevTools（F12）
2. 切换到设备模拟模式（Ctrl+Shift+M）
3. 测试以下设备：
   - iPhone SE (375x667)
   - iPad (768x1024)
   - Desktop (1920x1080)
4. 测试横屏和竖屏模式

**预期结果**：
- ✅ 移动端（≤768px）：侧边栏宽度100%，FAB位置调整
- ✅ 平板（≤900px）：侧边栏宽度90vw，导航栏宽度82px
- ✅ 桌面（>900px）：侧边栏宽度480px，导航栏宽度96px
- ✅ 横屏模式：侧边栏添加滚动，高度适配
- ✅ FAB按钮不与侧边栏重叠

---

### 6. FAB位置计算测试
**目标**：验证FAB按钮智能避让BOSS页面元素

**步骤**：
1. 在BOSS招聘首页，观察FAB按钮位置
2. 滚动页面，观察FAB按钮是否自动调整位置避让右侧浮动元素
3. 快速滚动页面，观察FAB位置更新是否流畅（防抖生效）
4. 调整浏览器窗口大小，观察FAB位置是否正确更新

**预期结果**：
- ✅ FAB自动避让BOSS页面的侧边栏元素
- ✅ 位置更新有100ms防抖，避免频繁计算
- ✅ 使用IntersectionObserver监听动态内容
- ✅ 没有多个定时器竞争导致的位置跳动

---

### 7. 按钮Disabled状态测试
**目标**：验证按钮在不可用时正确禁用

**步骤（工作台）**：
1. 进入"工作台"标签
2. 观察"清理投递记录"按钮状态（无记录时应该禁用）
3. 开始投递，产生一些记录
4. 观察"清理投递记录"按钮状态（有记录时应该启用）
5. 点击"清理投递记录"
6. 观察按钮再次变为禁用状态

**步骤（运行记录）**：
1. 进入"运行记录"标签
2. 观察"清空日志"按钮状态（无日志时应该禁用）
3. 产生一些日志后，按钮应该启用

**步骤（账户）**：
1. 进入"账户"标签
2. 点击"清除所有敏感数据"按钮
3. 观察按钮显示loading状态（转圈图标）
4. 点击"保存变更"按钮
5. 观察按钮显示loading状态

**步骤（AI投递判定）**：
1. 进入"投递判定"标签
2. 修改一些设置
3. 点击"保存判定规则"按钮
4. 观察按钮显示loading状态（虽然操作很快）

**步骤（AI配置 - API Key管理）**：
1. 进入"AI 配置"标签
2. 点击"新增配置"
3. 填写API信息
4. 点击"暂存"按钮
5. 观察按钮显示loading状态

**预期结果**：
- ✅ 无数据时按钮禁用（opacity: 0.5, cursor: not-allowed）
- ✅ 有数据时按钮启用
- ✅ 禁用状态下点击无响应
- ✅ 异步操作期间显示loading状态（转圈图标）
- ✅ 操作完成后loading状态消失
